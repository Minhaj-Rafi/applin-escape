# GitHub browser release guide

This repository is prepared for browser-only upload and Windows building.

## 1. Upload the source

Create or open the target repository on GitHub. Choose **Add file > Upload files**
and upload the contents of the `applin_escape` folder, not the outer folder itself.
The repository root must directly contain `main.py`, `README.md`,
`requirements-build.txt` and `ApplinEscape.spec`.

The browser may skip the hidden `.github` directory. If it does, choose
**Add file > Create new file**, enter `.github/workflows/windows-build.yml`, paste
the matching file from this package and commit it to the default branch.

## 2. Build the Windows app

Open **Actions > Build Windows game > Run workflow**. Leave
**Create a draft GitHub release** disabled for the first build. The workflow:

1. installs pinned dependencies;
2. runs all automated tests;
3. creates `ApplinEscape.exe` with its app icon;
4. checks all bundled audio and release screens;
5. packages the complete app folder and checksum.

When it finishes, download the **ApplinEscape-Windows-Release-Candidate** artifact.
Inside it are `ApplinEscape-5.3.1-Windows-RC.zip` and its `.sha256` file.

## 3. Test the actual EXE

Extract the Windows RC ZIP. Do not run inside the ZIP. Keep `_internal` beside
`ApplinEscape.exe`. Complete `WINDOWS_PLAYTEST.md` and `RELEASE_CHECKLIST.md`,
especially DualSense USB/Bluetooth, challenge clipboard and save recovery.

## 4. Create the GitHub draft release

After the Windows checks pass, run the workflow again with:

- **Create a draft GitHub release:** enabled
- **Version tag:** `v5.3.1`

The workflow validates the tag against the game version and creates a draft release
containing the Windows ZIP and checksum. Open **Releases**, review the draft and
publish it only after the remaining rights and playtest checks are complete.

Do not upload the uncompressed `dist` directory as the release download. Use the
versioned ZIP generated by the workflow.
